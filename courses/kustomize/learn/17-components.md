## Core concept

Overlays stack in a line: each one builds on exactly one thing below it. That
breaks down for optional features — a cache, TLS, debug tooling — that any
environment may or may not want. Ten environments and three features would
need an overlay per combination.

A **component** is a reusable piece of kustomization that is mixed *into*
its parent rather than built underneath it:

```yaml
# components/cache/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1alpha1
kind: Component
resources: [redis.yaml]
patches:
- target: {kind: Deployment}
  patch: ...

# prod/kustomization.yaml
resources: [../base]
components: [../components/cache]
```

The difference from a base is where its work happens. A base is built on its
own and hands back finished resources. A component runs **inside** the
parent's build, on the parent's resources:

```
  parent:  resources ──► generators ──► components ──► transformers
                                          │
           component (each, in order):    resources ──► generators
                                          ──► its components ──► transformers
                                              (on everything the parent has)
```

So a component's patch can reach the base's Deployment, its prefix renames
the parent's resources as well as its own, and its generator can `merge` into
a ConfigMap generated by the parent or by an earlier component. Components
run in the order listed, after the parent's generators and before the
parent's own transformers — which then apply to everything, the components'
resources included.

The kinds are kept apart. A `Component` uses apiVersion
`kustomize.config.k8s.io/v1alpha1`, may not be listed under `resources`, and
a `Kustomization` may not be listed under `components`. A component directory
can still be built directly, as the root of a build.

## Hints

<details><summary>Nudge</summary>

Give `build` the resources to start from. A base starts from none; a
component starts from its parent's.
</details>

<details><summary>Approach</summary>

Tell `build` which kind the directory must hold — Kustomization for a
resource, Component for a component, either for the root — and check it right
after loading.
</details>
